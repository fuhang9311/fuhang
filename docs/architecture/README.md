# 系统架构文档

## 概述

本文档描述了基于 Kubernetes、Nacos 和灵犀2.0 网关的微服务系统架构。该架构采用分层设计，实现了从应用接入到业务服务的完整流程。

## 架构层次说明

### 第一层：K8S 集群环境
**职责：** 提供容器编排和管理能力
- 自动化部署和扩展
- 服务发现和负载均衡
- 资源调度和管理
- 故障恢复和自愈

### 第二层：应用接入层
**职责：** 用户端应用入口
- **应用1**：用户端应用系统
- **应用2**：其他用户端应用系统
- 提供用户交互界面
- 发起业务请求

### 第三层：灵犀2.0 网关层
**职责：** 统一流量入口和安全控制
- **认证网关**
  - 统一认证入口
  - 身份验证和授权
  - Token 管理
  - 请求路由转发
- **用户上下文转换**
  - 处理用户身份信息
  - 转换用户上下文
  - 权限信息传递

### 第四层：服务注册与发现
**职责：** 微服务注册和配置管理
- **Nacos**
  - 服务注册与发现
  - 配置管理中心
  - 健康检查
  - 动态配置推送
  - 服务元数据管理

### 第五层：核心业务服务层
**职责：** 实现核心业务逻辑
- **用户中心**：用户信息管理、用户生命周期管理
- **认证中心**：身份认证、权限验证、SSO 单点登录
- **学籍管理**：学生信息管理、学籍档案管理
- **公告中心**：公告发布、公告管理、消息推送
- **消息中心**：站内信、消息通知、消息队列
- **文件中心**：文件上传、文件存储、文件下载

### 第六层：基础管理功能层
**职责：** 提供系统管理和配置功能

**第一行：组织架构管理**
- **用户管理**：用户增删改查、用户状态管理
- **角色管理**：角色定义、角色权限分配
- **部门管理**：组织架构管理、部门层级关系

**第二行：权限和岗位管理**
- **菜单管理**：菜单配置、菜单权限关联
- **权限控制**：权限定义、权限分配、访问控制
- **岗位管理**：岗位定义、岗位职责配置

## 数据流向

```
应用接入层 (应用1/应用2)
    ↓
灵犀2.0 网关层 (认证网关 → 用户上下文转换)
    ↓
服务注册与发现 (Nacos)
    ↓
核心业务服务层 (6个核心服务)
    ↓
基础管理功能层 (6个管理模块)
```

## 技术栈

### 容器编排
- **Kubernetes (K8S)**：容器编排平台，提供自动化部署、扩展和管理

### 服务治理
- **Nacos**：服务注册中心和配置中心
  - 服务注册与发现
  - 动态配置管理
  - 服务健康检查

### API 网关
- **灵犀2.0**：统一网关平台
  - 认证和授权
  - 请求路由
  - 流量控制
  - 安全防护

### 微服务架构
- 服务拆分：按业务领域划分微服务
- 服务通信：基于 HTTP/REST 或 RPC
- 服务治理：服务注册、发现、配置管理

## 架构特点

### 1. 分层清晰
六层架构设计，职责明确，便于维护和扩展

### 2. 高可用性
- K8S 提供容器级别的高可用
- Nacos 集群保证注册中心可用性
- 微服务支持多实例部署

### 3. 可扩展性
- 微服务可独立扩展
- K8S 支持自动扩缩容
- 新服务可快速接入

### 4. 安全性
- 灵犀2.0 网关统一认证
- 权限控制精细化管理
- 服务间通信安全保障

### 5. 可观测性
- 服务注册信息可视化
- 健康检查和监控
- 配置变更可追踪

## 后续优化方向

1. **服务网格 (Service Mesh)**：考虑引入 Istio 等服务网格技术
2. **分布式追踪**：集成 Zipkin 或 Jaeger 实现全链路追踪
3. **统一监控**：集成 Prometheus + Grafana 监控体系
4. **日志收集**：ELK 或 EFK 日志收集和分析
5. **DevOps**：CI/CD 流水线自动化部署
